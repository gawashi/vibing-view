<objective>
Stand up the timeframe-switching spine end-to-end: widen the `Timeframe` union to all 7 values, add the FMP intraday endpoints (1m/5m/15m/1h) with correct New-York→UTC timestamp conversion and recent-only initial spans, and render a TradingView-style always-visible timeframe button row that re-queries and repaints the chart on click. Daily (D) keeps its P1 full-EOD behavior; intraday timeframes become fully functional. W and M buttons render (fixed 7-button set) but their derivation lands in Plan 02.

Purpose: This is the phase's tracer — the thinnest path that touches shared type → provider → schema → (existing cache/IPC pass-through) → renderer api → chart → UI. Proving it end-to-end on the first commit catches any architectural dead-end (timeframe threading, intraday tz correctness, per-timeframe query separation) before the four expansion plans build on it.
Output: A chart whose timeframe a user can switch across 1m/5m/15m/1h/D, each rendering real cached-or-fetched candles.

## Phase Goal (MVP user story)

**As a** chart user, **I want to** switch a symbol across all timeframes and pan through history, **so that** I can study price at any resolution — and when the free tier can't serve a timeframe, I see why instead of a broken chart.

This plan delivers the first vertical slice of that story: switching across the fetchable timeframes.
