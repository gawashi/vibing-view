## Visual Hierarchy

- **Primary focal point:** unchanged — the chart canvas remains dominant. The timeframe row sits directly above the chart (D-10: always visible, single row, TradingView-style) as a secondary control strip, not competing visually with the candles.
- **Secondary focus:** the timeframe button row itself — must be scannable at a glance (which timeframes are available vs gated).
- **Gated buttons are visually demoted, not hidden:** per D-13, a gated button stays in the row (same position, same label) but renders at reduced opacity/muted text color with a small lock or clock badge — the user always sees the full 1m–M set and which ones are currently reachable, never a shifting/reflowing row.

### Icon Usage
- Lock icon (`Lock`, lucide-react) and clock icon (`Clock`, lucide-react) are the only icon-only elements introduced this phase, and both are exceptions to Phase 1's "no icon-only buttons" rule because they are **non-interactive status badges** riding on an already-labeled button ("1m" + badge), not a bare clickable icon.
- Both badges MUST carry a native `title`/tooltip (shadcn Tooltip) explaining the specific reason (D-14: distinct copy for plan-gated vs rate-limited) — never a bare glyph with no explanation.
- The mid-session rate-limit toast (D-15) uses a `Clock` or `AlertTriangle` icon paired with visible text — no icon-only toast.

## Color

Inherited from Phase 1 — no new hues introduced (reuse existing tokens; do not add a color for "gated" — express it via opacity/muted-text + icon per D-13/D-14, keeping the 60/30/10 split intact):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B0E11` | App background, chart canvas background (unchanged) |
| Secondary (30%) | `#151920` | Timeframe row container background, matches search bar/header surface (unchanged) |
| Accent (10%) | `#2E7DE1` | Reserved for: the **selected/active timeframe button** (new usage this phase) — same accent token as Phase 1's primary CTAs/focus rings, no new color added |
| Destructive | `#E5484D` | Reserved for: unchanged Phase 1 uses only (API-key clear, error banners). NOT used for gated buttons — gated is a muted/neutral state, not an error/destructive one, to avoid visually conflating "unavailable on your plan" with "something broke" |
| Text primary | `#E4E7EB` | Active/available timeframe button label text |
| Text muted | `#8B92A0` | Gated timeframe button label text (also the existing Phase 1 muted-label token) — same value used for both flavors of gating; the Lock vs Clock icon + tooltip copy is what differentiates plan-gated from rate-limited, not color |

Accent reserved for: primary CTA buttons, input focus rings, selected list-row state (Phase 1) + the active/selected timeframe button (Phase 2) — nothing else.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Timeframe row label (implicit, no heading) | Buttons read exactly: "1m", "5m", "15m", "1h", "D", "W", "M" |
| Gated tooltip — requires higher plan | "Requires a paid FMP plan. Your current key doesn't support this timeframe." |

| Mid-session rate-limit toast (D-15: currently-viewed timeframe hits the limit) | "Rate limit reached for {timeframe}. Showing cached data — new bars will load once the limit resets." |
| Pan-triggered gap-fetch (background, non-blocking) | No user-facing copy needed for the success path — silent background fetch. If the gap-fetch itself hits a rate limit mid-pan, reuse the mid-session rate-limit toast above. |
| Empty state | Not applicable this phase — D-15 guarantees gated timeframes are unselectable, so the chart is never shown empty for a gated reason. Phase 1's chart-loading/error copy still applies to the initial fetch. |

## UI Considerations

Applicable state considerations resolved: 6 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| gated/disabled | timeframe button (toggle-group item) | ✅ covered | Grayed out + Lock/Clock badge, unselectable, tooltip shows the distinct reason copy above (D-13/D-14) |

| error (mid-session) | chart area, rate-limit hit while viewing an active timeframe | ✅ covered | Toast notification (copy above) fires once; cached bars remain visible per D-15, chart does not blank or error out |
| zero-one-many | timeframe button row | ✅ covered | Fixed set of exactly 7 buttons always rendered (1m/5m/15m/1h/D/W/M) — no variable count, no empty-row case |
| populated | timeframe button row | ✅ covered | All 7 always visible; availability (active vs gated) varies per D-19 capability probe, but the row itself never changes shape |
| reset-on-switch | chart view after timeframe click | ✅ covered | D-11: always resets to latest/`fitContent`-equivalent view on switch — no "restore scroll position" state to design for |
| overflow / long-text | gated tooltip copy on narrow window widths | 🧪 backstop | Tooltip copy above is 1–2 sentences; needs a visual check once the app shell's minimum window width is known (Phase 1 didn't declare one) to confirm the tooltip doesn't clip |
