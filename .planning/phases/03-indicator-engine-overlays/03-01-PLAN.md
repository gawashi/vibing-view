<objective>
Stand up the pluggable indicator engine end-to-end with a single working overlay: a
Simple Moving Average rendered on the price pane, added from a "+指標" menu, listed in a
top-left legend, and recomputed (never refetched) on symbol/timeframe switch.

This is the TRACER slice — one thin path through every layer the phase touches (module
contract → math → module → registry → store → chart reconcile → add-menu → legend →
App wiring). It proves the architecture in one commit before Plan 02 (edit form + legend
controls) and Plan 03 (Bollinger Bands) expand horizontally on top of it.

Purpose: de-risk the whole phase — the reconcile effect, the registry-driven UI, and the
"recompute from cached bars, no refetch" contract (D-26/D-31) are the load-bearing pieces;
prove them once, on a trivial indicator, before adding more.
Output: a runnable app where clicking +指標 → MA draws an SMA line and a legend row; plus
the required Vitest math cross-check (DESIGN §2).
</objective>

<assumption_delta_decision>
Detector: fires (pluralization) — the store moves from `activeSymbol`-only + a single
candlestick series to a first-class `indicators[]` collection, and the registry generalizes
"an indicator".

- **Primary noun:** the indicator-instance collection (`store.indicators[]`).
- **Decision:** `no-change` (designed-plural-from-start). There is no prior *singular*
  indicator being demoted — DESIGN §3 and D-31 model `indicators[]` as first-class from the
  outset. The candlestick series is the price data, not an indicator, so no promote/demote
  applies.
- **Rationale:** one line — the generalized identity (an indicator module in the registry,
  instantiated N times) is the design's starting point, not a retrofit onto a singular case.
- **Invariant:** every registered module round-trips add → compute → render through the same
  path. Covered concretely by this tracer (`ma`) and Plan 03 (`bb`) — a dedicated
  registry-round-trip test is deferred as YAGNI (two real modules already exercise the path;
  add the test only when a third module lands with a shape the first two didn't cover).
</assumption_delta_decision>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user input → indicator params | User-entered period / type / source / color feed pure client-side math and lightweight-charts series options only. No network, no persistence, no privileged IPC this phase. |
| renderer ↔ main IPC | Unchanged — indicators add NO new IPC channel and no new TanStack Query key (DESIGN §Architecture). Existing ohlcv/capabilities IPC is untouched. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Denial of Service | Chart reconcile recompute / addIndicator | low | mitigate | O(n) client compute over already-loaded bars; period clamped to FieldDesc.min ≥ 1; unbounded instance count is intentional (IND-07) but each add is one cheap array pass. Short debounce available on live edit (Plan 02, D-26) if typing ever feels heavy. |
| T-03-02 | Tampering | indicator param values | low | accept | Params are numbers / enum strings / hex colors used as math inputs and chart options — never innerHTML/eval/SQL. Canon-security breadcrumb (dropped): XSS/injection is N/A — a color is a hex string set as a series option, not markup. |
| T-03-03 | Spoofing / Repudiation / Info-disclosure / Elevation | — | n/a | accept | No secrets, no auth, no network, no persistence, no privileged op introduced this phase — these vectors do not apply. |
| T-03-SC | Tampering (supply chain) | npm installs | n/a | accept | ZERO new dependencies this phase (package.json unchanged; all UI parts installed in P1/P2; native `<input type=color>` used instead of a color-picker dep). No install to audit — legitimacy gate not triggered. |
