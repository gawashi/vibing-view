# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Scope: "+指標" add-indicator control, top-left overlay legend (per-instance toggle/edit/delete),
> schema-driven parameter edit form, indicator color palette, and Bollinger Band translucent fill.
> Sub-pane indicators (Volume/RSI/MACD), crosshair sync, TV-exact correctness gate, disk persistence,
> and multi-chart grids remain out of scope (Phases 4–5) — this contract does not cover them.

## Visual Hierarchy

- **Primary focal point:** unchanged — the chart canvas (candlesticks + overlays) remains dominant. MA/BB
  lines and the BB band fill render *on* the price series, never competing with it for a separate layout
  region.
- **Secondary focus:** the "+指標" control, placed near `TimeframeRow` in `App`'s chart-top toolbar
  (D-22) — a labeled button ("+ 指標"), not an icon-only control (consistent with Phase 1's "no
  icon-only buttons" rule; the `Plus` icon pairs with the visible label).
- **Tertiary, floating layer:** the overlay legend (D-23), absolute top-left inside the chart canvas.
  It must read as translucent/recessed chrome over the candles — `bg-card/80` (matching Phase 2's
  gap-loading indicator precedent in `Chart.tsx`) — never a solid opaque panel that competes with the
  chart's own visual weight.
- **Per-instance color is the differentiator, not size or weight:** every MA/BB line and its legend
  swatch share one palette-assigned color (D-30); the legend row's leading swatch (small filled circle,
  ~8px) is the only visual link between a legend entry and its chart line — this must be pixel-color-exact,
  not an approximation.

### Icon Usage
- Legend row icons (`Eye`/`EyeOff`, `Settings2`, `X`) are icon-only, and are an explicit, scoped exception
  to Phase 1's "no icon-only buttons" rule for the same reason Phase 2's Lock/Clock badges were: they are
  compact repeated per-row controls where a text label would break the one-line-per-instance layout that
  D-23 requires to avoid burning chart area. Each MUST carry a shadcn `Tooltip` ("Show/Hide", "Edit
  parameters", "Remove") and an `aria-label` — never a bare unexplained glyph.
- The "+指標" trigger itself is NOT icon-only — it renders `Plus` + visible text "+ 指標" (or "Add
  indicator"), consistent with Phase 1's rule for primary/discoverable actions.

## Color

Inherited base tokens from Phase 1/2 (unchanged) plus a new **indicator palette** scoped to this phase:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B0E11` | App background, chart canvas background (unchanged) |
| Secondary (30%) | `#151920` | Legend background (`bg-card/80` = `#151920` at 80% opacity), edit-form dialog surface (unchanged) |
| Accent (10%) | `#2E7DE1` | Reserved for: the "+指標" button (primary CTA for this phase, same token as Phase 1's search/save CTAs), edit-form Save/Apply affordance if the dialog uses one — **never** used as a default indicator line color (would visually collide with the app's one reserved accent meaning) |
| Destructive | `#E5484D` | Reserved for: the legend row's delete (`X`) icon on hover/focus only — confirmation copy below. NOT used for any indicator line/band color (would read as an error state) |
| Text primary | `#E4E7EB` | Legend labels, edit-form field labels (unchanged) |
| Text muted | `#8B92A0` | Edit-form helper text (min/step hints), legend row when an instance is hidden (`visible: false`) — dims the label to Text-muted rather than removing the row |

**Indicator palette (D-30 — new this phase, round-robin assigned by add order):**

| Order | Hex | Notes |
|-------|-----|-------|
| 1 | `#F5A623` (amber) | First instance added |
| 2 | `#A78BFA` (violet) | |
| 3 | `#2DD4BF` (teal) | |
| 4 | `#F472B6` (pink) | |
| 5 | `#FACC15` (yellow) | |
| 6 | `#38BDF8` (sky) | Cycle repeats from index 1 after 6 instances — acceptable per D-30 (no artificial instance-count limit, but visual disambiguation beyond 6 simultaneous overlays is a known, accepted degradation, not a blocker) |

These six hues are deliberately disjoint from: chart candle colors (`#22C55E` up / `#EF4444` down),
the app accent (`#2E7DE1`), and destructive (`#E5484D`) — so no indicator line is ever mistakable for a
candle, the primary CTA, or an error state. BB uses **one** palette color per instance for all three
lines (upper/middle/lower) plus the band fill at 15% opacity of that same color — not three separate
hues per BB instance (keeps one BB instance reading as one visual unit in the legend, matching the
`BB 20,2` single-row label in D-23).

Accent reserved for: primary CTA buttons, input focus rings, selected list-row/timeframe state (Phase
1/2) — nothing new added in Phase 3; the indicator palette above is deliberately a *separate* set of
hues, never the accent token.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (add indicator) | "+ 指標" button label; menu items "MA" (moving average) and "BB" (Bollinger Bands) |
| Legend row label format | `MA 20` (period only, SMA/EMA distinguished via edit form, not the label) / `BB 20,2` (period,σ-multiplier) — per D-30 |
| Legend row tooltips | Eye/EyeOff icon: "Show" / "Hide" · Settings2 icon: "Edit parameters" · X icon: "Remove" |
| Edit-form field labels | "Period", "Type" (SMA/EMA toggle), "Source" (close/open/high/low/hl2/hlc3), "Std Dev ×" (BB only), "Color" |
| Empty state (no indicators added) | No dedicated empty-state copy — the legend simply does not render when zero instances exist (an empty floating panel over the chart would be visual noise the chart doesn't need); the "+指標" button itself is always visible as the entry point |
| Error state | Not applicable this phase — indicators compute client-side from already-cached bars (no network call, no failure mode to surface per D-26/DESIGN.md §Architecture); if `barsRef.current` is empty (symbol still loading), newly-added instances simply render no line until bars arrive, with no error copy needed |
| Destructive confirmation | Remove indicator (`X` icon): **no confirmation dialog** — single click removes immediately. Rationale: removing an overlay is trivially reversible (re-add via "+指標" with one click, defaults reappear per D-28) and low-stakes (no data loss, purely a display toggle) — unlike Phase 1's API-key removal, which does warrant a confirm dialog. This is a deliberate exception; document it so the checker doesn't flag "destructive action without confirmation" as a gap. |

## UI Considerations

State-coverage probe (`ui-consideration-probe.cjs`) over the 4 described surfaces — E1 "+指標" menu,
E2 overlay legend, E3 edit form, E4 BB band fill — flagged 22 applicable categories (E4 unclassified →
manual review). Resolved: **11 covered, 1 backstop, 10 n/a (dismissed with reason), 0 unresolved.**
The legend vertical-overflow row was raised to the user and resolved to internal scroll.

| Element | Category | Status | Resolution / Reason |
|---------|----------|--------|---------------------|
| E1 "+指標" menu | populated | ✅ covered | Exactly two items (MA, BB) always present; happy-path is the only path |
| E1 "+指標" menu | zero-one-many | ✅ covered | Fixed 2-item menu (D-22); IND-01's pluggable registry lets P4 add items to the same menu with no UI redesign — not a variable-count concern now |
| E1 "+指標" menu | long-text | ✅ covered | Menu labels are short fixed strings ("MA"/"BB"); no free text, no wrap risk |
| E1 "+指標" menu | empty / loading / error / partial / overflow | ⊘ n/a | Static JSX control, no data source: nothing to load, fail, partially fill, or empty; 2 items never overflow (a registry that grows the list far enough inherits the same internal-scroll rule as E2) |
| E2 overlay legend | empty | ✅ covered | Legend does not render at zero instances (Copywriting Contract — no empty-state row); "+指標" is the sole always-visible entry point |
| E2 overlay legend | populated | ✅ covered | Rows stack top-to-bottom in add order; each carries swatch + label + eye/gear/×; no pagination, no row-count truncation |
| E2 overlay legend | zero-one-many | ✅ covered | 0 = no legend; 1 or many = identical per-row layout, no count-based copy variance, no upper limit (IND-07) |
| E2 overlay legend | loading | ✅ covered | New instance added to state/legend optimistically (D-26 "no refetch"); its line renders empty until `barsRef.current` populates, then draws on the next recompute pass — no spinner (sub-second, piggybacks the existing chart-loading state) |
| E2 overlay legend | overflow (vertical) | ✅ covered | **User decision:** legend panel caps at a max-height (~50% of canvas) and scrolls internally; every row stays reachable and the chart stays uncovered no matter how many indicators are stacked (IND-07 — no count limit) |
| E2 overlay legend | overflow (palette) | ✅ covered | Indicator palette repeats from index 1 after 6 — accepted degradation per D-30; IND-07's "no count limit" outranks indefinite color disambiguation |
| E2 overlay legend | long-text | 🧪 backstop | `{ statement: "Legend labels are bounded computed strings (`{type} {period}` / `BB {period},{mult}`), not free text, and must not wrap or clip inside the fixed row height", verification: backstop }` — visual check once a worst-case `BB 200,3.5` (3-digit period + decimal σ) actually renders |
| E2 overlay legend | error / partial | ⊘ n/a | Client-side compute from cached bars — no network/submit failure mode (D-26); an instance is wholly present or removed, never a partial row |
| E3 edit form | empty | ✅ covered | Form opens pre-filled from the instance's current params (module defaults on first add, D-28) — never a blank form |
| E3 edit form | error (validation) | ✅ covered | `FieldDesc.min`/`step` (DESIGN.md §1) drive the native number input's own min/step; out-of-range values clamp to `min` rather than surfacing an error message — keeps D-26's immediate-recompute-on-keystroke contract simple |
| E3 edit form | long-text | ✅ covered | Field labels are fixed short strings ("Period"/"Type"/"Source"/"Std Dev ×"/"Color"); no wrap risk |
| E3 edit form | loading / partial | ⊘ n/a | Params are in-memory (no async load); the schema-generated form always renders the module's full field set — no partial-form state |
| E4 BB band fill | partial (unclassified) | ✅ covered | `compute()` returns `upper`/`middle`/`lower` atomically (DESIGN.md §1); one `setData`-per-output pass drives all 3 lines + the band primitive from a single `compute` call — no partial-band lag. Band-fill *implementation* risk (custom primitive vs 3-line fallback) is tracked in DESIGN.md §5, not a UI-state gap |
