<user_story>
**As a** chart user, **I want to** add RSI in its own synchronized sub-pane and read its value at any timestamp via a crosshair, **so that** I can judge overbought/oversold momentum against TradingView-matching values without leaving my chart.

(Derived directly from the ROADMAP Phase 4 Goal line; no scope invented. RSI is the tracer that proves every sub-pane mechanic — separate pane, fixed scale, param-driven guide lines + zone, per-pane legend, and crosshair sync — before Volume and MACD replicate it.)
</user_story>

<objective>
Land the module-contract extension and the full generic sub-pane rendering machinery by driving ONE indicator (RSI) end-to-end through every layer: contract → math → module → registry → Chart pane-reconcile → per-pane legend → crosshair readout → unit test. This is the phase's highest-risk slice (per-pane HTML legend over drag-resizable canvas panes + synchronized crosshair, RESEARCH Q2/Landmines #2/#3) — it is proven ONCE here so Volume (Plan 02) and MACD (Plan 03) become drop-in module additions that touch zero Chart.tsx code.

Purpose: prove the architecture end-to-end before replicating. If the per-pane legend / crosshair recipe is wrong, we find out after one commit, not ten.
Output: a real registered RSI indicator rendering in its own 0-100 pane with 70/30 guides+zone, a working synchronized crosshair, and the generic separate-pane + histogram + guides + band + scale machinery all later indicators reuse.
</objective>

<assumption_delta_decision>
Primary noun: "indicator module (overlay-or-separate)". The Phase 3 contract modeled only overlay indicators (singular pane concept); this phase generalizes to overlay-or-separate.
Decision: **promote** — add an additive `pane?: 'overlay' | 'separate'` field to `IndicatorModule` defaulting to `'overlay'`. Existing ma/bb are unchanged (they omit it → default overlay); RSI/MACD/Volume set `'separate'`. No singular→plural rewrite, no accepted debt. DESIGN §1 already resolved this by promoting the general representation.
</assumption_delta_decision>
