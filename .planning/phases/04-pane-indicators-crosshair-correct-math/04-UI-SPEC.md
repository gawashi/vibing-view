# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Scope: Volume/RSI/MACD sub-panes below the price pane, per-pane legends with cursor-value readout,
> synchronized crosshair across all panes, RSI 70/30 zone shading, MACD zero-line + 4-color histogram,
> volume up/down coloring. Correctness-gate math (IND-09) has no UI surface (Vitest only, no UI-SPEC entry).
> Disk-persisted pane heights, multi-chart grids, and cross-chart crosshair sync remain out of scope
> (Phase 5 / v1.x) — this contract does not cover them.

## Visual Hierarchy

- **Primary focal point:** unchanged — the price pane (candlesticks + Phase 3 overlays) remains the
  dominant, tallest region. Sub-panes are subordinate — shorter by default, stacked below, and never
  compete with the price pane for visual weight.
- **Pane order (top to bottom):** Price pane → Volume (fixed, always present per D-34) → any user-added
  RSI/MACD panes in add order (D-33: one instance = one pane). Volume's fixed position immediately
  below price matches TradingView convention and this project's own established pattern.
- **Secondary focus, per pane:** each sub-pane's own top-left legend (D-37) — a translucent floating
  chrome row (`bg-card/80`), replicating the price-pane legend's visual language exactly so all panes
  read as one consistent system, not five different UI styles.
- **Crosshair as the unifying interaction:** a single vertical crosshair line spans all panes
  (price + every sub-pane) at the same x (time) position — this is the visual proof of "synchronized,"
  more important than any individual pane's styling. The horizontal crosshair line only appears in the
  pane under the pointer (each pane has its own y-scale — RSI 0-100, MACD auto, Volume auto).
- **Resize handles (D-32):** lightweight-charts' native pane-separator drag handles — thin (a few px)
  horizontal dividers between panes, standard library styling, no custom app chrome needed or wanted.
- **Removal collapses cleanly (D-36):** when a sub-pane's last instance is removed, that pane's vertical
  space is immediately reclaimed — panes below shift up, no empty placeholder track ever lingers.

### Icon Usage
- Per-pane legend icons (`Eye`/`EyeOff`, `Settings2`, `X`) are icon-only, extending the same explicit,
  scoped exception established in Phase 3 (D-37 explicitly re-applies D-23/24's icon-only legend
  convention to sub-panes). Each MUST carry a `Tooltip` and `aria-label`, identical wording to Phase 3
  ("Show"/"Hide", "Edit parameters", "Remove").
- No new icon-only controls introduced for the crosshair itself — cursor values render as plain text
  inserted into the existing legend row, no icon needed (D-38).
- Volume's legend is display-only (no gear/eye/× — D-34 treats it as a fixed, non-removable pane, not a
  managed instance); it shows only the label + cursor-value text, no action icons at all.

## UI Considerations

State-coverage probe (`ui-consideration-probe.cjs`) over the 4 described surfaces — E1 Volume pane
(fixed), E2 RSI/MACD sub-panes (added via "+指標"), E3 per-pane legend + cursor readout, E4 crosshair
sync — flagged applicable categories against Phase 3's already-resolved menu/legend/edit-form baseline
(reused, not re-probed). Resolved: **9 covered, 1 backstop, 3 n/a (dismissed with reason), 0 unresolved.**

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| populated | E1 Volume pane | ✅ covered | Always rendered once a symbol has bars (`Bar.volume` already present per-bar since Phase 1) — no zero-state, no toggle-off (D-34) |
| zero-one-many | E2 RSI/MACD panes | ✅ covered | 0 = pane absent entirely; 1 or many = one pane per instance stacking downward (D-33), no upper limit (IND-07), identical to Phase 3's overlay zero-one-many resolution |
| overflow (vertical, many panes) | E2 RSI/MACD panes | ✅ covered | **User decision (D-32):** each pane is drag-resizable; lightweight-charts allocates remaining canvas height across panes, panes shrink rather than clip — degrades gracefully with many stacked panes, same "no artificial limit" value as Phase 3 |
| removal / collapse | E2 RSI/MACD panes | ✅ covered | **User decision (D-36):** last-instance removal deletes the pane and panes below shift up immediately — no empty placeholder track |
| loading | E2 RSI/MACD panes | ✅ covered | New instance added optimistically (unchanged D-26 pattern); pane renders empty until next recompute pass populates from `barsRef.current` — no spinner, matches Phase 3's overlay-loading resolution |
| non-hover / default state | E3 legend cursor readout | ✅ covered | **User decision (D-40):** absent cursor shows latest-bar values, never blank — applies uniformly to price + all sub-panes |
| long-text (MACD 3-value readout) | E3 legend cursor readout | 🧪 backstop | `{ statement: "MACD readout ('MACD {v} Signal {v} Hist {v}') at 2-decimal precision with large price-scale symbols (4+ integer digits) must not wrap or clip within the fixed-height legend row", verification: backstop }` — visual check once a high-priced symbol (e.g. 4-digit stock) is actually rendered |
| sync accuracy | E4 crosshair | ✅ covered | **User decision:** a single vertical crosshair line spans price pane + all sub-panes at identical x; each pane's own legend updates from the same `subscribeCrosshairMove` event so all values are guaranteed same-timestamp, never independently-lagged reads |
| error / partial | E1/E2/E4 | ⊘ n/a | All computation is synchronous client-side math over already-cached bars (D-26 rationale, unchanged) — no network path exists to fail or partially return |
| empty (zero bars, symbol still loading) | E1 Volume pane | ⊘ n/a | Matches Phase 3's precedent: newly-selected symbol with no bars yet simply renders no bars in any pane (price, volume, or added sub-panes) until data arrives — no distinct per-pane empty copy needed beyond the app's existing "loading symbol" state (Phase 1/2 concern, unchanged) |
| color/palette exhaustion (RSI/MACD line colors) | E3 legend | ⊘ n/a | Reuses the same 6-hue palette and round-robin/repeat behavior already accepted in Phase 3 (D-30) — no new exhaustion case introduced by sub-panes |
