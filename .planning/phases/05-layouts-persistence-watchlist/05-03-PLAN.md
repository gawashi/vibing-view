<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disk (`userData/layouts.json` `named`) → main → renderer | Saved named-layout JSON is untrusted on load |
| package registry → dev machine | `npx shadcn add dropdown-menu` copies component source + pulls a transitive dependency |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-L1 | Tampering/DoS | `layoutStore` save/delete/rename + `getLayout` load | medium | mitigate | Each named layout validated via `parseWorkspace` on load (corrupt entry → skip/abort switch, never wipe state); every mutation is a read-modify-atomic-write of the whole file so a crash can't partially write or lose sibling layouts |
| T-05-L2 | Tampering (supply chain) | `npx shadcn add dropdown-menu` → `@radix-ui/react-dropdown-menu` | low | accept | Official shadcn registry, first-party Radix primitive, same family/trust posture as the 5 already-installed `@radix-ui/*` deps (UI-SPEC Registry Safety signed off); not an `[ASSUMED]`/`[SUS]` package, so no blocking-human legitimacy checkpoint is required |
| T-05-L3 | Tampering | layout name as a persistence key | low | accept | Names are object keys inside one JSON file, never used as filesystem paths (no path traversal) and rendered as escaped React text (no injection) |
</threat_model>
