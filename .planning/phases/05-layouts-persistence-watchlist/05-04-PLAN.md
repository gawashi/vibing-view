<objective>
Add the **persistent watchlist** — the capstone of the v1 goal line. A collapsible left sidebar lists watched symbols (symbol + name + cached close, no fetch), persists to its own `watchlist.json`, and clicking a row loads that symbol into the focused active cell (WATCH-02). Symbols are added via a star on each search result (D-65), removed via a hover X, and reordered via hand-written HTML5 drag-and-drop on a drag handle (D-66). The watchlist is single/global across all layouts (D-62).

Purpose: deliver SC4 — "manage a watchlist that persists across sessions; clicking a symbol loads it into the active chart."
Output: `Watchlist` sidebar, `watchlistStore` (atomic JSON), `watchlist:get/set` IPC, watchlist store slice, and the search-result star.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disk (`userData/watchlist.json`) → main → renderer | Persisted watchlist JSON is untrusted on load |
| renderer → main (typed IPC `watchlist:*`) | Watchlist array crosses the process boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-W1 | Tampering/DoS | `watchlistStore.getWatchlist` (startup load) | low | mitigate | Coerce to `WatchlistItem[]`, drop malformed entries, corrupt/parse-fail → `[]` (never throw); a SEPARATE `watchlist.json` means a corrupt watchlist can never affect saved layouts; atomic `writeJsonFile` on every change |
| T-05-W2 | Information Disclosure / Injection | persisted `name`/`symbol` rendered in sidebar rows | low | accept | React escapes text nodes by default; symbols pass as data through parameterized IPC/query keys, never interpolated into SQL/shell — no injection surface |
</threat_model>
