# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Scope: multi-chart grid (1x1/2x1/2x2) with independent cells, active-cell focus affordance, grid-shape
> switcher, named-layout menu (save/save-as/rename/delete/switch), collapsible left watchlist sidebar
> (add/remove/reorder/click-to-load). Out of scope: pane-height persistence (D-60), 3x3+/custom grids
> (D-51), multiple watchlists (D-62), cross-cell crosshair sync (out of scope v1).

## Spacing Scale

Declared values (inherited from Phase 1-4, unchanged — must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between grid-shape icon buttons; gap between watchlist row's drag-handle/symbol/price/remove segments |
| sm | 8px | Padding inside each grid cell's own chart legend (unchanged per-pane convention); padding inside each watchlist row; gap between header controls |
| md | 16px | Gap between grid cells (CSS `grid-gap`); vertical gap between watchlist rows' visual grouping (none needed — rows are contiguous, 8px row padding is sufficient) |
| lg | 24px | Padding inside the layout dropdown menu and Save-As/Rename dialog body |
| xl | 32px | Header horizontal gaps (unchanged) |
| 2xl | 48px | Watchlist sidebar's collapsed-state icon-only rail width is **not** 48px — see Visual Hierarchy for the two explicit sidebar widths |
| 3xl | 64px | Not used this phase |

Exceptions: none — desktop mouse-driven app, no 44px touch-target exception needed (unchanged).
Grid-cell gap uses `md` (16px) so the CSS grid reads as one system, not stacked isolated panels.

## Visual Hierarchy

- **Primary focal point:** the grid of chart cells remains the dominant region (unchanged from single-
  chart Phase 1-4, now generalized to 1-4 cells). No single cell is visually privileged over another
  except via the focus ring — size/weight is identical across cells regardless of grid shape.
- **Header layout (left to right):** app title/active-symbol readout (unchanged) → **grid-shape icon row**
  (new, D-52 — `ToggleGroup` single-select, icons `Square`/`Columns2`/`Grid2x2`) → **layout menu**
  (new, D-56 — `DropdownMenu` trigger button, label "Layout" + `ChevronDown`) → existing search bar →
  settings. Grid-shape and layout-menu sit as two visually distinct controls (icon row = shape, dropdown
  = named save/restore), matching D-52's explicit "separate UI, separate role" decision.
- **Active-cell focus (D-53):** the focused cell gets `ring-2 ring-primary ring-offset-2
  ring-offset-background` — a clearly visible glowing accent outline around the cell's outer edge.
  Clicking anywhere in a cell (its chart canvas, its legend, its per-pane controls) sets it active.
  Exactly one cell is always active when ≥1 cell exists (default: cell 0 / top-left).
- **Grid cell layout:** CSS grid, `gap-4` (16px), each cell a flex column hosting its own `Chart`
  instance — unchanged internal cell layout from Phase 4 (price pane + sub-panes + legends + crosshair),
  now replicated per cell. Cell count and shape come from the active grid preset (1x1/2x1/2x2); hidden
  cells (D-54, shrink case) are unmounted from the DOM but retain their store state.
- **Watchlist sidebar (D-63):** a left `<aside>`, two states — **expanded** (240px fixed width, full
  rows: drag handle + symbol + name + cached close + remove) and **collapsed** (0px width, fully hidden,
  not an icon rail — simplest binary state, avoids inventing a third "icon-only" width this phase didn't
  ask for). Toggle button (`PanelLeftClose`/`PanelLeftOpen`) sits in the header, left-most position.
  Default: expanded on first launch (matches "workspace as home base" intent); persisted per D-58's
  "current state" auto-save scope, not a separate concern (**Claude's discretion** confirms sidebar
  open/closed persists with the general session-state auto-save, not the named-layout model — it is a UI
  chrome preference, not part of LAYOUT-02's serializable config model).
- **Watchlist row layout:** `flex items-center gap-1 px-2 py-2`, drag handle at far left (visible on row
  hover only, `cursor-grab`), symbol (semibold) + name (truncated, muted) in the middle, cached close
  price right-aligned before the remove `X` (visible on row hover only, far right). Clicking anywhere on
  the row *except* the drag handle or the `X` loads the symbol into the active cell (D-53/WATCH-02).
- **Layout dropdown menu (D-56) structure, top to bottom:** "Save" (overwrites current named layout if
  one is active, else acts as "Save As") → "Save As New…" (opens name-prompt dialog) → "Rename…" (only
  enabled when a named layout is active; opens name-prompt dialog prefilled with current name) →
  separator → "Delete…" (destructive text color, opens confirmation dialog) → separator → list of saved
  layout names (click to switch, D-58 auto-saves current state first) → if list is empty: single disabled
  muted-text row "No saved layouts yet".
- **Grid-expand duplication (D-55):** no distinct visual treatment needed — the new cell simply renders
  with the same symbol/timeframe/indicators as the active cell at the moment of expansion; this is a data
  behavior, not a visual one.

### Icon Usage
- Grid-shape icons (`Square`/`Columns2`/`Grid2x2`) are icon-only inside a `ToggleGroup`, extending the
  same explicit icon-only exception already established in Phase 3/4 (D-23/24/37) — each MUST carry a
  `Tooltip` + `aria-label`: "1x1", "2x1", "2x2".
- Watchlist toggle (`PanelLeftClose`/`PanelLeftOpen`) is icon-only, `Tooltip` + `aria-label`: "Hide
  watchlist" / "Show watchlist".
- Watchlist row drag handle (`GripVertical`) and remove (`X`) are icon-only, hover-revealed (not always
  visible, to keep rows visually quiet at rest — the row's Body-weight symbol text is the primary visual
  element, not its action icons). Each carries `aria-label`: "Reorder {symbol}" / "Remove {symbol} from
  watchlist". No `Tooltip` wrapper required on hover-revealed icons since the label is self-evident on
  reveal (consistent with minimal-chrome intent) — **Claude's discretion**, not a strict requirement.
- Search result star/`+` (D-65) is icon-only (`Star`, filled once added, outline otherwise), `Tooltip` +
  `aria-label`: "Add to watchlist" / "Already in watchlist".
- Layout dropdown trigger uses a text label ("Layout") + `ChevronDown` — **not** icon-only, since it is a
  named/discoverable action distinct from the icon-only grid-shape row right next to it.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (this phase) | "Layout" dropdown trigger button — opens the save/restore menu (D-56). Grid-shape row has no CTA copy (icon-only, tooltip-labeled). |
| Layout menu items | "Save" · "Save As New…" · "Rename…" · "Delete…" · saved-layout names (as entered by user) · empty state: "No saved layouts yet" (muted, disabled) |
| Save-As / Rename dialog | Title: "Save layout as" / "Rename layout". Field label: "Name". Placeholder: "e.g. Morning watch". Confirm button: "Save" / "Rename". Cancel: "Cancel". |
| Duplicate-name handling | On Save As with a name that already exists: inline field error "A layout named "{name}" already exists." — blocks submit rather than silently overwriting or auto-numbering (safer default, avoids surprising data loss) |
| Delete confirmation dialog | Title: "Delete layout?" Body: "This removes the saved layout "{name}". This can't be undone." Confirm button (destructive): "Delete". Cancel: "Cancel". |
| Watchlist empty state | "Your watchlist is empty. Add symbols from search results." (shown in place of the row list when watchlist has zero items) |
| Watchlist row — no cached price | Close-price cell renders empty (blank), never "—" or "N/A" — D-64 explicitly says no extra fetch, and a truly blank cell reads as "not loaded" without implying an error |
| Watchlist add button (search results) | Icon-only `Star`, tooltip "Add to watchlist" (unfilled) / "Already in watchlist" (filled, disabled — no remove-from-search, removal only happens in the sidebar) |
| Error state | Not applicable — layout/watchlist persistence is local JSON via IPC (D-67), no network path; a write failure (rare: disk full/permission) surfaces via the existing `sonner` toast pattern: "Couldn't save layout. Try again." (reused Phase 1 error-toast convention, not a new UI surface) |
| Destructive actions in this phase | (1) Delete named layout — confirmation dialog required (data loss, irreversible, D-56). (2) Remove watchlist symbol (`X`) — **no confirmation**, same low-stakes reversible-by-re-adding precedent as Phase 3/4's indicator removal (D-36) — re-adding via search star is trivial. |

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| zero-one-many | E1 grid cells | ✅ covered | 1/2/4-cell presets only (D-51); no zero-cell state — grid always has ≥1 cell once a symbol exists, matching Phase 1's existing "no symbol yet" empty state as the only true zero-state |
| shrink/expand data retention | E1 grid cells | ✅ covered | **User decision (D-54/55):** shrinking retains hidden-cell config in the model (unmount, not delete); expanding duplicates the active cell's full config — no data loss either direction |
| overflow / vertical scroll | E3 watchlist rows | ✅ covered | Row list is a scrollable `overflow-y-auto` column within the fixed 240px sidebar — unbounded watchlist length (no cap per WATCH-01) scrolls rather than clipping or resizing the sidebar |

| empty | E2 layout menu (no saved layouts) | ✅ covered | Disabled muted "No saved layouts yet" row instead of an empty blank menu section |
| destructive / irreversible | E2 delete named layout | ✅ covered | Confirmation dialog required (only genuinely irreversible action this phase) — see Copywriting |

| non-hover / default state | E3 watchlist row icons | ✅ covered | Drag handle + remove `X` hover-revealed; row's core info (symbol/name/price) always visible regardless of hover, matching the "core content never depends on hover" principle |
| startup / first-run | E4 auto-restore | ✅ covered | **User decision (D-59):** first-ever launch (no saved state, no named layout) defaults to 1x1 + AAPL, extending existing D-06/07 |
| loading (per-cell restore) | E1 grid cells on restore | ✅ covered | Each cell's OHLCV fetch is independently cache-first (P1 read-through, unchanged) — cells populate as their own query resolves, no app-wide blocking spinner; matches existing per-symbol loading precedent |

| partial / invalid persisted state | E4 startup restore | ✅ covered | **User decision:** restore all valid fields; fill missing or invalid ones with defaults (unresolvable symbol → skip/default, missing sidebar flag → expanded, absent field from an older schema → its default). | error / partial | E2/E3 persistence writes | ⊘ n/a | Local JSON write via IPC (D-67); no network path, no partial-success state possible — a rare disk-level failure is a single all-or-nothing toast (see Copywriting), not a per-field partial state |
